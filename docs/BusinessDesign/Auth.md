# Auth / Session / JWT 설계

## 주 목적
- Phase1 초기 인증은 Session 기반으로 구현한다.
- 이후 팀 초대, 팀 가입, 외부 URL 기반 흐름을 위해 JWT와 Redis 기반 토큰 저장 구조로 전환한다.
- 인증 방식 전환은 사용자, 팀, 폴더, 파일 도메인의 권한 감사 흐름과 충돌하지 않아야 한다.

## 현재 인증 방향
- 요청 유지 관리는 Session으로 수행한다.
- 로그인과 전역 권한 관리는 Spring Security를 활용한다.
- 전역 역할은 관리자와 일반 사용자로 구분한다.
- 일반 사용자의 폴더/파일 접근 관리는 전역 Role이 아니라 ACL로 수행한다.

## JWT 전환 목표
- 사용자 계정 세션을 JWT 기반으로 전환한다.
- JWT를 활용해 팀 초대 토큰을 발급한다.
- JWT 토큰은 Redis에 저장해 유효성, 만료, 폐기 여부를 관리한다.
- JWT 전환 시 사용자, 팀, 폴더, 파일의 기존 뼈대 기능을 실제 정상 비즈니스 로직으로 고도화한다.

## Redis 토큰 저장 정책
- 팀 초대 토큰은 Redis에 저장한다.
- Redis TTL을 통해 초대 토큰의 유효기간을 관리한다.
- Redis에서 삭제되었거나 만료된 토큰은 거절한다.
- 초대 토큰은 TTL 내에서는 재사용 가능하다.
- 하나의 초대 토큰으로 여러 사용자를 초대할 수 있다.

## 팀 초대 토큰 검증
- 사용자가 팀 가입 URL 또는 가입 API로 초대 토큰을 제출한다.
- 서버는 JWT를 분해하고 서명을 검증한다.
- 서버는 Redis에 저장된 토큰 존재 여부와 TTL을 확인한다.
- 서버는 토큰 발급자인 초대자가 여전히 해당 팀 소속인지 확인한다.
- 검증이 끝나면 사용자를 일반 멤버 역할로 팀에 가입시킨다.

## 전환 시 유의사항
- JWT 전환은 로그인 기능만의 문제가 아니라 팀 초대/가입 기능의 선행 조건이다.
- Redis 장애, 토큰 만료, 토큰 폐기, 초대자 탈퇴 케이스를 명확히 분리해야 한다.
- Session 기반 인증과 JWT 기반 인증이 공존하는 전환 기간의 정책을 별도로 정해야 한다.
