# Admin 도메인 설계

## 주 목적
- Admin은 서비스 운영, 모니터링, 통계 확인을 위한 전역 관리자 역할이다.
- Admin은 일반 사용자의 파일과 폴더를 임의로 열람하는 역할이 아니다.
- 일반 사용자의 파일/폴더 접근은 ACL 정책을 우선한다.

## 관리자 권한 범위
- 관리자는 주로 모니터링 페이지와 통계 페이지를 사용한다.
- 관리자는 임의로 불특정 일반 사용자의 폴더와 파일을 볼 수 없다.
- 관리자 권한은 서비스 운영 행위와 일반 사용자 자원 접근 행위를 분리해 설계한다.

## 관리자 생성
- 관리자 생성은 전용 API와 페이지를 통해 수행한다.
- 관리자 생성 URL 또는 API는 이미 관리자 권한을 가진 사용자가 호출해야 한다.
- 관리자 계정 생성 이후의 기본 계정 흐름은 일반 사용자 계정과 동일하게 처리한다.

## 일반 사용자와의 관계
- 관리자도 사용자 계정의 한 종류로 취급한다.
- 관리자 권한은 전역 역할로 구분한다.
- 전역 역할은 테이블이 아니라 사용자 테이블 내 특정 컬럼 또는 ENUM 값으로 구분한다.

## 향후 고려사항
- 관리자 통계 기능
- 감사 로그 조회
- 운영성 이벤트 모니터링
- 관리자 행위에 대한 별도 감사 로그
