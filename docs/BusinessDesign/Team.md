

# Team 도메인 설계

## 주 목적
- Team은 여러 사용자가 하나의 팀 폴더 스코프를 공유하기 위한 협업 단위다.
- 팀 생성 시 생성자는 팀 대표 역할을 가지며, 팀 폴더 진입점이 함께 생성된다.
- 팀의 멤버십, 초대, 가입, 강퇴, 역할 변경은 사용자-팀 관계 데이터를 기준으로 관리한다.

## 팀 역할
- 팀 내 역할은 테이블이 아닌 ENUM으로 관리한다.
- 사용자별 팀 역할은 사용자-팀 관계 테이블에 저장한다.
- Phase1 기준 팀 역할은 ACL 및 PermissionBitMask와 결합해 행위 가능 여부를 판단할 수 있어야 한다.
- 팀 폴더에서 HEAD, MANAGER 계열 역할은 ACL을 우회할 수 있는 관리 권한으로 취급한다.

## 팀 생성
- 팀 생성 API는 팀 도메인과 사용자-팀 관계를 함께 생성한다.
- 팀 생성자는 자동으로 팀 대표 역할을 가진다.
- 팀 생성 시 팀 Entry Folder를 자동 생성한다.
- 팀 Entry Folder는 팀 폴더 트리의 내부 진입점이며, 사용자에게 직접 노출하지 않는다.

## 팀 조회
- 사용자는 본인이 소속된 팀 목록을 조회할 수 있다.
- 사용자는 본인이 소속된 팀의 상세 정보를 조회할 수 있다.
- 팀원 리스트와 팀원 상세 정보는 팀 내 역할 구분 없이 모든 팀원이 조회할 수 있도록 설계한다.

## 팀 수정 및 폐쇄
- Phase1에서 팀 수정은 팀 이름 변경만 지원한다.
- 팀 폐쇄는 soft delete 방식으로 처리한다.
- 팀 수정, 폐쇄, 역할 변경 등 관리성 행위는 추후 ACL 또는 PermissionBitMask 기반 권한 감사와 연결한다.

## 팀 초대
- 팀 초대는 JWT 토큰 기반으로 설계한다.
- 초대 토큰은 Redis에 저장하고 TTL을 통해 유효기간을 관리한다.
- 하나의 초대 토큰으로 여러 명을 초대할 수 있다.
- 초대 토큰은 TTL 내에서는 재사용 가능하다.
- Redis에서 삭제되었거나 만료된 초대 토큰은 거절한다.
- 초대 토큰 검증 시 초대자가 여전히 해당 팀 소속 멤버인지 확인한다.

## 팀 가입
- 사용자는 초대 토큰이 포함된 URL 또는 가입 API를 통해 팀 가입을 요청한다.
- 서버는 JWT 초대 토큰을 분해하고 Redis 저장 상태와 TTL을 검증한다.
- 최초 가입자는 일반 멤버 역할로 팀에 추가한다.
- 가입 성공 시 사용자-팀 관계 데이터를 생성한다.

## 팀 강퇴
- 팀 강퇴는 사용자-팀 관계 데이터를 soft delete 처리한다.
- 강퇴 권한은 추후 팀 역할, ACL, PermissionBitMask와 연결해 제한한다.

## 팀 역할 승격
- 팀 내 사용자는 다른 사용자의 팀 역할을 승격할 수 있다.
- 초기 설계에서는 제약을 단순하게 두되, ACL 개발 이후 PermissionBitMask 기반 행위 제어를 추가한다.
- 역할 승격은 팀 폴더 접근 권한과 연결될 수 있으므로 감사 대상 행위로 취급한다.

## 팀 자진 탈퇴
- 사용자는 본인이 속한 팀에서 자진 탈퇴할 수 있다.
- 단, 팀 대표 또는 소유권 개념이 있는 사용자가 탈퇴하는 경우 팀 리더십/소유권 승계 정책이 필요하다.
- 소유권 승계 정책이 확정되기 전까지 팀 대표의 자진 탈퇴는 재설계 대상이다.

## UI 설계

### Team + Folder 좌측트리뷰 (컨텐츠관리메뉴)
- 팀은 각각 Section + Panel 식으로 구성한다.
- 각 팀 클릭은 accordion 식으로 Expandable + Collapsible UI로 folder Tree를 제공한다.
