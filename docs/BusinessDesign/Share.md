# Share 도메인 설계

## 주 목적
- Share는 파일과 폴더를 특정 사용자, 특정 팀, 또는 URL 기반으로 접근 가능하게 만드는 기능이다.
- 공유 기능은 별도 권한 모델을 새로 만들기보다는 ACL 생성을 통해 구현한다.
- 공유받은 파일과 폴더는 사용자의 직접 소유 자원이 아니므로 별도 리스팅 정책이 필요하다.

## 공유 대상
- 파일 공유
- 폴더 공유
- 사용자 대상 공유
- 팀 대상 공유
- URL 기반 공유

## 공유와 ACL
- 공유 시 각 오브젝트 타입에 맞는 ACL을 추가한다.
- 폴더 공유는 FolderAcl을 생성하거나 변경한다.
- 파일 공유는 기본적으로 폴더 ACL을 따르되, 파일 단위 명시 제어가 필요하면 FileAcl을 사용한다.
- 공유 권한은 ACL의 subjectType, subjectUserId, subjectTeamId, effectType, permissionBitMask를 통해 표현한다.
- 공유 회수는 ACL을 soft delete 하거나 비활성화하는 방식으로 처리한다.

## 사용자 공유
- 특정 사용자에게 파일 또는 폴더 접근 권한을 부여한다.
- subjectType은 USER를 사용한다.
- 개인 폴더의 공유는 사용자가 직접 ACL을 조작하지 않고 공유 기능을 통해서만 수행한다.

## 팀 공유
- 특정 팀에게 파일 또는 폴더 접근 권한을 부여한다.
- subjectType은 TEAM을 사용한다.
- 사용자가 소속된 팀에게 공유된 항목도 공유받은 항목 리스팅 대상에 포함한다.

## URL 공유
- URL 기반 공유는 별도 토큰 또는 식별자를 통해 접근한다.
- URL 공유는 공개 범위, 만료, 권한 범위를 별도로 정의해야 한다.
- URL 공유 기능은 Phase1 후순위 또는 Phase2 대상이다.

## 공유받은 항목 리스팅
- 공유받은 파일과 공유받은 폴더를 조회할 수 있어야 한다.
- 조회 시 사용자의 직접 USER ACL뿐 아니라 사용자가 소속된 TEAM ACL도 함께 고려한다.
- ACL을 조회해 리스팅할 수 있도록 한다.
- 공유받은 항목은 소유 항목과 UI/응답에서 구분할 수 있어야 한다.

## 권한 변경과 회수
- 공유 권한은 변경 가능해야 한다.
- 공유 권한 회수는 ACL 비활성화 또는 soft delete로 처리한다.
- 권한 변경과 회수는 CONTROL 이상의 권한이 필요한 관리 행위로 취급한다.
